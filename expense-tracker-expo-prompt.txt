## Supabase operations to implement
Always authenticate via Clerk and filter by `user_id`.

### Categories
- fetch all for user, order by `name` ASC
- create (`spent: 0`)
- update by `id` + `user_id`
- delete by `id` + `user_id`

### Transactions
- fetch all for user with join `expense_categories(*)`
- order by `date` DESC, then `created_at` DESC
- create
- update
- toggle settlement (`needs_settlement`)
- delete

### Persons
- fetch all for user, order by `name` ASC
- create
- update (can exist in store/API even if UI has no rename screen)
- delete

### Monthly summaries
- fetch all for user, order by `month` DESC
- upsert on conflict `user_id, month`

## Zustand store behavior
Mirror the web store pattern:
- `initialize()` loads categories, transactions, persons, monthly summaries
- optimistic local updates for CRUD
- after transaction create/update/delete, refresh categories in background to sync spent amounts
- settlement toggle is optimistic with revert on failure

## Overview calculations
```
totalIncome  = Σ amount where type === "income" (after date + person filters)
totalExpense = Σ amount where type === "expense" (same filters)

totalBudget =
  month → Σ category.monthly_budget
  year  → Σ category.monthly_budget * 12
  all   → 0

budgetProgress = totalBudget > 0 ? (totalExpense / totalBudget) * 100 : 0
```

Cards:
1. Income
2. Expenses
3. Budget Health (`{budgetProgress}% Used`, spent/budget, progress bar)

Progress colors:
- >100 rose/red
- >80 amber/yellow
- else emerald/green

Also show:
- category spending chart
- recent activity list (limit 10)
